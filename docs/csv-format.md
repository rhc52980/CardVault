# CSV import format

What CardVault accepts when importing a collection, and how to produce a file that
imports cleanly — particularly when the rows are generated by scanning cards rather
than typed by hand.

Files can be `.csv`, `.tsv` or `.txt`. Drop one on the **Import CSV** tab or paste
rows directly.

## The short version

```
Card ID,Name,Set,Number,Quantity,Condition,Notes
base1-4,Charizard,Base,4/102,1,NM,id: high
```

Only **Name** or **Number** is genuinely required. Everything else is optional, and
columns that aren't recognised are ignored and listed back to you on the review
screen.

## Columns

Header matching is case-insensitive and treats `_` and `-` as spaces, so `card_id`,
`Card-ID` and `CARD ID` are all the same column.

| Column | Also accepted as | Value | Default |
| --- | --- | --- | --- |
| `Card ID` | `ID`, `pokemontcg id`, `api id` | A pokemontcg.io id, `base1-4` | — |
| `Name` | `Card Name`, `Card`, `Product Name`, `Title` | The name as printed | — |
| `Set` | `Set Name`, `Edition`, `Expansion` | `Base`, `151` | — |
| `Set Code` | `PTCGO Code`, `Set Abbreviation`, `Abbr` | `BS`, `SVI` | — |
| `Number` | `Card Number`, `Collector Number`, `No`, `#` | **As printed:** `4/102` | — |
| `Quantity` | `Qty`, `Count`, `Copies`, `Amount` | Whole number | `1` |
| `Condition` | `Cond` | `NM` `LP` `MP` `HP` `DMG` | `NM` |
| `Variant` | `Printing`, `Finish`, `Foil`, `Parallel` | See below | `Normal` |
| `Purchase Price` | `Paid`, `Cost`, `Buy Price` | `12.50` or `$12.50` | — |
| `Purchase Date` | `Acquired`, `Date Added`, `Date` | `1999-01-09` | — |
| `Grade` | `Graded`, `Cert` | A slab grade | — |
| `Language` | `Lang`, `Locale` | `English`, `Japanese`, `ja`, `jp` | `English` |
| `Location` | `Storage`, `Binder`, `Box`, `Where` | Free text | — |
| `Notes` | `Note`, `Comment`, `Description` | Free text | — |

Use `Condition` rather than `Grade` for card wear — `Grade` means a slab's
certification and is a different field.

### Values are normalised on the way in

- **Condition** — `Near Mint`, `Lightly Played`, `Excellent`, `Good`, `Poor` and the
  short codes all map onto `NM` / `LP` / `MP` / `HP` / `DMG`. Anything unrecognised
  becomes `NM` silently, so it is worth restricting a generator to the five codes.
- **Variant** — anything containing "reverse" becomes `reverseHolofoil`; "1st" or
  "first" becomes a 1st Edition printing; "holo" or "foil" becomes `holofoil`;
  everything else is `normal`. If a row asks for a printing the card was never issued
  in, the import falls back to a real one and says so on the row.
- **Language** — names, ISO codes and the country codes people reach for all map
  onto one code: `Japanese`, `japanese`, `JA` and `JP` are all `ja`. Anything
  unrecognised becomes English, so a generator is best restricted to the codes.
- **Purchase price** — currency symbols and thousands separators are stripped.

### A non-English card is imported unpriced

Every catalogue price is for the English printing, so a row that arrives as Japanese
is stored with no market value rather than the English one. Give it a value of your
own on the card and it counts towards your total normally.

## Write the number the way the card prints it

`4/102`, not `4`.

The denominator narrows to the handful of sets of exactly that size, which for a bare
number is the difference between one match and one per set ever printed. It is the
single most useful thing in the file: a column of numbers written this way resolves
without a `Set` column at all.

Alphanumeric numbers work unchanged (`SWSH039`, `TG04`). A non-numeric denominator
like `SV49/SV94` is accepted but yields no set narrowing, so pair those with a name.

## If a Card ID is generated rather than read

A Pokémon card does not carry its pokemontcg.io id anywhere on it. The printed
identifiers are a name, a collector number and a set symbol — so anything filling in a
`Card ID` column is *inferring* it, and an inferred id that is wrong is still
perfectly valid. It resolves to exactly one real card and would otherwise arrive
looking every bit as matched as a correct one.

So when the id is generated, **always include `Name` and `Number` as well**. The
import compares them against the card the id resolved to and flags any disagreement
as **Check this one**, showing both readings beside the artwork and refusing to let
the row be added without a decision.

Names are compared loosely enough that "Charizard" against "Charizard ex" is
agreement rather than a flag, and `004` against `4` is the same number. An id with no
name or number beside it imports unchecked.

Leaving `Card ID` empty is always safe — the row resolves from the name and number
instead. An empty cell is better than a guessed one.

## A prompt for generating rows from card images

> For each card image, output one CSV row:
> `Card ID,Name,Set,Number,Quantity,Condition,Notes`
>
> - **Name** — exactly as printed, including any suffix (`ex`, `V`, `VMAX`).
> - **Number** — the collector number *as printed, with its denominator*: `4/102`,
>   `045/094`, `SWSH039`. Never strip it to just the numerator.
> - **Set** — the set name if you can identify the symbol; leave empty if unsure.
> - **Card ID** — your best guess at the pokemontcg.io id (`base1-4`). This is **not
>   printed on the card**, so you are inferring it. Leave it empty rather than guess
>   when you are not confident.
> - **Quantity** — `1` unless told otherwise.
> - **Condition** — one of `NM`, `LP`, `MP`, `HP`, `DMG`.
> - **Notes** — your confidence in the Card ID, e.g. `id: high` / `id: low`.
>
> Quote any field containing a comma. Output only the header row and data rows.

Confidence in `Notes` costs nothing — it is a recognised column, it carries through
onto the card, and it gives you something to sort by when a batch looks shaky.

## Example

```
Card ID,Name,Set,Number,Quantity,Condition,Notes
base1-4,Charizard,Base,4/102,1,NM,id: high
base1-58,Pikachu,Base,58/102,3,LP,id: high
,Alakazam,Base,1/102,1,NM,set symbol unclear
sv3pt5-6,Charizard ex,151,6/165,1,NM,id: medium
```

The third row carries no id and resolves from `1/102` alone.

## What happens next

Nothing is written to your collection until you press the button. Every row lands in
one of six states — see [CSV import](../README.md#csv-import) in the README for what
each means and what the review screen lets you do about it.

Rows that don't make it in can be exported straight back out as a CSV, carrying what
your file said rather than what the import suspected, ready to correct and re-import.
